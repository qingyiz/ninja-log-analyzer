## 问题与目标

### 问题陈述

用户保存、重命名或分类 Ninja 日志后，当前软件会因文件名限制拒绝加载；新的 v7 日志也会被拒绝。即使成功加载旧日志，泳道较多时看不到下方内容，界面没有解释泳道与核心数的区别，也没有机器环境上下文和可交付的完整报告。

### 目标与成功指标

- v4、v5、v7 的合法日志均可解析，v7 命令哈希正确保留。
- 任意名称的文件只要内容首行是 Ninja log 签名即可加载；目录定位同样按内容识别。
- 24 条或更多泳道能够通过垂直滚动完整查看，数据减少后滚动范围同步收缩。
- 成功加载后始终可看到“导出完整报告”入口，导出的单文件 HTML 包含当前批次全部任务，而非仅包含筛选结果。
- 界面和报告都解释泳道含义、与 CPU 核心数的关系以及日志可证明/不可证明的信息。
- 界面和报告展示分析时机器负载快照及其时间、逻辑处理器数，并明确其不是构建时历史负载或 CPU 使用率。

### 非目标

- 不改变 Ninja 日志格式，也不推断日志未记录的精确构建时 CPU/内存使用率。
- 不把泳道数强行限制为 CPU 核心数。
- 不新增 PDF、Excel 或联网报告服务；本次完整报告为可离线打开的单文件 HTML。
- 不重构已经完成的四层架构，不改变分析算法的批次定义。

## 角色、术语与范围

### 角色

| 角色 | 目标 | 权限或限制 |
|---|---|---|
| 构建性能分析者 | 打开各种保存方式的 Ninja 日志、理解并发与环境、分享完整结果 | 只能依据日志和当前机器快照分析 |

### 术语

| 术语 | 精确定义 |
|---|---|
| 内容签名 | 文件首行匹配 `# ninja log v<整数>`；是否受支持由解析器继续判定 |
| 当前批次 | 分析器选定、当前 UI 正在展示的 `BatchAnalysis` 对应记录集合 |
| 泳道 | 为避免时间区间视觉重叠而分配的最少显示行；不是线程或 CPU 核心 |
| 完整报告 | 包含当前批次所有记录、摘要、分类、洞察、并发解释和环境快照的自包含 HTML |
| 机器负载快照 | 日志成功加载时，分析机器的系统 load average、逻辑处理器数、平台与采集时间 |

### 系统边界与依赖

- 范围内：core 解析/定位、application 负载采集/报告导出、gui 滚动/解释/导出交互、测试与 README。
- 范围外：持续采样监控、远程机器探测、构建过程中采集遥测、PDF/云端报告。
- 外部依赖：Qt Core/Widgets/Test；类 Unix 平台的 `getloadavg`（不可用时显式降级）。

## 用户旅程

1. 用户选择一个已重命名的日志文件或包含日志的目录。
2. 软件按内容签名定位文件，解析 v4/v5/v7，分析并展示结果。
3. 用户滚动查看全部并发泳道，并从说明中理解泳道数为何可能大于 8 核。
4. 用户查看加载时机器负载快照及限制。
5. 用户可筛选界面，但点击始终可见的“导出完整报告”，选择路径并得到包含当前批次全部任务的 HTML。

## 功能需求

### REQ-001：兼容 v7 并按内容识别日志

**用户故事：** 作为构建性能分析者，我希望加载 v4/v5/v7 以及重命名后的 Ninja 日志，从而保留和分类日志时不受固定文件名约束。

- 优先级：Must
- 前置条件：输入是一个可读文件或目录。
- 结果/副作用：返回确定的日志文件路径与解析结果，不修改源文件。

#### 验收标准

- AC-001.1：合法 v4、v5、v7 日志均能解析；v5/v7 的第五列按十六进制命令哈希保留，v4 无命令哈希。
- AC-001.2：任意文件名的直接文件输入，只要首行是 Ninja log 签名即可进入解析。
- AC-001.3：目录输入递归查找内容签名匹配的常规文件，并沿用稳定、可预测的候选选择顺序。
- AC-001.4：签名存在但版本不支持（例如 v6/v8）、字段非法、文件不可读或目录中无候选时，返回可理解的错误，不崩溃。
- AC-001.5：内容探测只读取有界前缀，不因大文件目录扫描而读取全部内容。

### REQ-002：完整可滚动的并发时间线与泳道说明

**用户故事：** 作为构建性能分析者，我希望查看所有泳道并理解它们的意义，从而不会把显示行误认为 CPU 核心。

- 优先级：Must
- 前置条件：已有成功分析的当前批次。
- 结果/副作用：时间线尺寸随记录和泳道数更新。

#### 验收标准

- AC-002.1：当内容高度超过视口时，时间线出现可操作的垂直滚动条并可查看最下方泳道。
- AC-002.2：当筛选后内容高度小于视口时，滚动范围同步缩小，不保留陈旧空白高度。
- AC-002.3：界面和报告明确说明泳道是“不重叠显示行/最小并发重叠需求”，不等于 CPU 核心、线程或 Ninja worker。
- AC-002.4：当出现“8 个逻辑处理器、24 条泳道”等情况时，说明可能与 `-j` 并行度、I/O 等待、逻辑处理器、区间重叠和批次推断有关，同时声明日志不能单独证明精确原因。

### REQ-003：导出当前批次完整 HTML 报告

**用户故事：** 作为构建性能分析者，我希望把分析结果导出为可独立分享的完整报告，从而离线复盘或交付给其他人。

- 优先级：Must
- 前置条件：至少成功加载并分析过一个日志。
- 结果/副作用：只创建或原子替换用户选择的 HTML 文件。

#### 验收标准

- AC-003.1：主窗口在最小支持尺寸下也能看到“导出完整报告”入口；未加载时禁用，成功分析后启用。
- AC-003.2：用户选择 `.html` 路径后，软件导出 UTF-8、自包含 CSS、可离线打开的 HTML，并显示成功或失败反馈。
- AC-003.3：报告包含源文件、日志版本、当前批次范围、有效/忽略行数、批次数、manifest 状态、五项摘要指标、耗时分类、洞察、并发/泳道说明、机器负载快照和全部当前批次任务。
- AC-003.4：界面筛选不会裁剪报告；报告任务数始终等于当前批次总记录数，并按分析结果的慢任务顺序输出。
- AC-003.5：目标路径为空、不可写或写入失败时，不报告成功；动态文本必须 HTML 转义，避免路径/目标名破坏文档结构。

### REQ-004：展示当前机器负载上下文和数据限制

**用户故事：** 作为构建性能分析者，我希望看到分析机器的负载上下文，从而判断环境差异可能对编译耗时的解释产生影响。

- 优先级：Must
- 前置条件：成功加载日志。
- 结果/副作用：在加载完成时采集一次稳定快照，供界面和报告共同使用。

#### 验收标准

- AC-004.1：快照至少包含采集时间、逻辑处理器数、系统/架构，以及平台可用时的 1/5/15 分钟 load average。
- AC-004.2：平台或 API 不支持时显式显示“不可用”，不伪造为 0。
- AC-004.3：界面和报告明确说明快照来自“分析时当前机器”，不是构建时历史负载，也不是 CPU 利用率；日志可能来自另一台机器。
- AC-004.4：一次成功加载对应的界面和报告使用同一快照，后续筛选不重新采样。

## 约束、假设与风险

### 已确认约束

- 依赖方向与 macOS 交付契约必须保持（FACT-007、FACT-008）。
- 负载信息只能作为分析时上下文，不能伪装成构建时遥测（FACT-006）。

### 待验证假设

- ASM-001：v7 仍使用五列记录并以十六进制保存命令哈希；由 Ninja 官方实现与回归样本验证。
- ASM-002：Qt 的 `QScrollArea` 在子控件最小高度更新并启用可调整尺寸后会正确更新垂直范围；由 GUI 测试验证。

### 风险

- RISK-001：按内容递归扫描目录会接触更多文件；通过只读有界前缀和常规文件过滤控制。
- RISK-002：load average 在 Windows 等平台语义/可用性不同；必须显式降级，不做跨平台伪等价。
- RISK-003：完整报告在超大日志上可能较大；本次保持线性导出，不嵌入大图或二进制资源。
