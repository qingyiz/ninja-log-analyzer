## 问题与目标

### 问题陈述

CMake/Ninja 构建慢时，开发者只能看到文本日志中的相对时间和输出路径，难以快速回答“总耗时在哪里”“哪类步骤占用最多工作量”“哪些单步最慢”“并行度是否充分”。同时，日志可能包含多次 Ninja 运行，且步骤类型并不直接记录在 `.ninja_log` 中，因此直接求和容易产生误导。

### 目标与成功指标

- 用户在一个桌面窗口中选择 `.ninja_log` 文件或构建目录后即可完成分析。
- 对合法 v4/v5 日志，展示观察窗口、累计任务时间、任务数、最大/平均并行度、步骤类型汇总、最慢步骤、时间线和可解释的瓶颈提示。
- 对目录中的一个或多个日志提供确定、可见的选择过程。
- 对格式错误、部分坏行、缺少 manifest、空批次等情况给出用户可理解的结果，不崩溃、不修改构建目录。
- 核心解析和统计由自动化测试覆盖；在 FACT-004/005 的 Qt 6.4.3 Kit 上完成配置、编译和测试。

### 非目标

- 不执行、清理、重整或修改 Ninja 构建及 `.ninja_log`。
- 不从日志反推出 CPU、内存、磁盘 I/O 或缓存命中率；日志没有这些数据。
- 不把“慢步骤候选”宣称为严格关键路径；首版不完整解析 Ninja 依赖 DAG 和 dyndep。
- 不负责代码签名、公证、商店发布或安装包制作。
- 不接入远程构建服务或上传日志。

## 角色、术语与范围

### 角色

| 角色 | 目标 | 权限或限制 |
|---|---|---|
| C/C++/Qt 开发者 | 找到 Ninja 构建耗时瓶颈并定位到输出/规则 | 仅需读取本地构建文件 |
| 构建工程师 | 比较步骤类型、长尾和并行利用情况 | 需要明确统计口径和数据局限 |

### 术语

| 术语 | 精确定义 |
|---|---|
| 记录 | `.ninja_log` 中一条通过校验的制表符分隔数据行 |
| 任务耗时 | `end_ms - start_ms`，单位毫秒，要求非负 |
| 推断批次 | 按日志行顺序，当当前结束时间小于上一有效行结束时间时切分得到的连续记录组；它是启发式视图，不保证等价于一次真实构建 |
| 观察窗口 | 当前批次中最早开始到最晚结束的时间跨度 |
| 累计任务时间 | 当前批次所有任务耗时之和；并行任务会重复计入 |
| 平均并行度 | 累计任务时间 / 观察窗口；观察窗口为 0 时定义为 0 |
| 最大并行度 | 对所有任务开始/结束事件扫描得到的最大同时活动任务数；相同时间先处理结束再处理开始 |
| 步骤类型 | 优先根据 `build.ninja` 的 rule 名映射，无法映射时根据输出路径/扩展名推断的展示分类 |
| 瓶颈提示 | 基于已展示指标生成、同时说明判断依据的候选问题，不等价于硬件性能诊断或严格关键路径 |

### 系统边界与依赖

- 范围内：路径解析、递归日志发现、v4/v5 解析、manifest 规则补充、批次推断、指标计算、分类统计、最慢步骤、并发时间线、瓶颈提示、桌面交互。
- 范围外：运行构建、编辑 Ninja 文件、采集系统性能、远程传输、数据库持久化。
- 外部依赖：C++17、CMake、Qt Core/Widgets/Test；运行分析时不要求系统 PATH 中存在 Ninja。

## 用户旅程

1. 用户启动应用，在路径栏输入/粘贴 `.ninja_log` 或构建目录，也可使用“选择”按钮。
2. 用户点击“分析”；若目录下有多个日志，应用展示候选文件供用户选择。
3. 应用只读加载日志；若同目录可发现 `build.ninja`，补充 rule 和更可靠的步骤分类。
4. 应用默认展示最后一个推断批次，并允许切换其他推断批次或全部有效记录。
5. 用户查看总览卡片、类型汇总、最慢步骤、时间线和瓶颈提示，并通过搜索或类型过滤缩小范围。
6. 当日志存在坏行或分析口径受限时，用户在界面中看到警告和有效/忽略记录数。

## 功能需求

### REQ-001：解析文件或目录输入

**用户故事：** 作为开发者，我希望直接提供日志或构建目录，从而无需手工定位隐藏文件。

- 优先级：Must
- 前置条件：用户可读取目标路径。
- 结果/副作用：返回一个选定日志路径；不修改任何文件。

#### 验收标准

- AC-001.1：当输入是名为 `.ninja_log` 的可读普通文件时，系统应当选中该文件。
- AC-001.2：当输入是目录时，系统应当递归查找其中名为 `.ninja_log` 的普通文件，并按规范化绝对路径排序。
- AC-001.3：当目录中发现多个日志时，系统应当让用户明确选择一个候选项，取消选择不得覆盖当前分析结果。
- AC-001.4：如果路径不存在、不可读、不是支持的文件或目录中没有日志，系统应当显示包含原因的错误，且保持可继续输入的状态。

### REQ-002：可靠解析 Ninja 构建日志

**用户故事：** 作为构建工程师，我希望解析结果能区分有效记录与数据问题，从而信任后续统计。

- 优先级：Must
- 前置条件：已选定日志。
- 结果/副作用：在内存中生成记录和诊断；日志保持不变。

#### 验收标准

- AC-002.1：当首行是 `# ninja log v4` 或 `# ninja log v5` 时，系统应当按对应的五字段格式解析开始、结束、mtime、输出和最后字段，并保留原始行号。
- AC-002.2：当一行缺字段、整数无效、开始/结束为负或结束早于开始时，系统应当忽略该行、累计警告并继续解析后续行。
- AC-002.3：如果签名缺失、版本不受支持、文件不可读或没有有效记录，系统应当停止本次加载并显示可操作错误。
- AC-002.4：对 v5，系统应当把最后字段作为十六进制命令哈希校验和保存；对 v4，系统应当保留最后字段但不得伪称已得到可比较的 v5 哈希。
- AC-002.5：系统应当支持 CRLF/LF 行尾以及输出路径中的空格；字段分隔只以制表符为准。

### REQ-003：识别分析批次并补充步骤类型

**用户故事：** 作为开发者，我希望尽量把历史记录与当前构建分开，并知道每个任务属于哪类步骤，从而避免误读汇总。

- 优先级：Must
- 前置条件：日志已有有效记录。
- 结果/副作用：生成一个或多个推断批次及每条记录的规则/分类。

#### 验收标准

- AC-003.1：当有效行的结束时间相对上一有效行发生回退时，系统应当开始新的推断批次；否则记录保留在当前批次。
- AC-003.2：系统应当默认选中最后一个非空推断批次，并提供“全部有效记录”视图；界面必须把批次标为“推断”。
- AC-003.3：当日志附近存在 `build.ninja` 时，系统应当读取 build statement 的显式/隐式输出与 rule，并按规范化相对输出路径匹配日志记录。
- AC-003.4：系统应当优先按 rule 名把任务归入 C 编译、C++ 编译、CUDA 编译、Qt 自动生成、资源生成、静态库链接、共享库链接、可执行文件链接、自定义命令、其他；无 rule 匹配时按输出特征推断并标记来源。
- AC-003.5：如果 manifest 不存在或部分语法无法识别，系统应当继续完成日志分析，并在状态区说明使用了回退分类。

### REQ-004：计算可复核的构建指标

**用户故事：** 作为构建工程师，我希望获得定义明确的总体和分类统计，从而量化瓶颈。

- 优先级：Must
- 前置条件：当前分析视图至少有一条记录。
- 结果/副作用：生成汇总指标、分类聚合和排序结果。

#### 验收标准

- AC-004.1：系统应当展示任务数、观察窗口、累计任务时间、平均并行度和最大并行度，计算口径与“术语”一致。
- AC-004.2：系统应当按步骤类型展示任务数、累计时间、平均时间、最大时间以及占累计任务时间的比例。
- AC-004.3：系统应当按耗时降序展示最慢任务；耗时相同按输出路径稳定排序，并至少展示输出、类型、rule、开始、结束、耗时。
- AC-004.4：零耗时任务、相同起止时刻和重叠任务不得导致除零、负并发或不稳定排序。
- AC-004.5：所有面向用户的时长应当自动选择 ms、s、min 单位，同时保留足够精度区分结果。

### REQ-005：可视化时间分布和瓶颈候选

**用户故事：** 作为开发者，我希望一眼看到长任务、并发空洞和长尾，从而决定下一步优化对象。

- 优先级：Must
- 前置条件：指标已计算。
- 结果/副作用：界面随批次/过滤器变化同步更新。

#### 验收标准

- AC-005.1：系统应当使用摘要卡、类型汇总图/表、最慢任务表和按时间定位的并发时间线展示同一当前数据集。
- AC-005.2：时间线应当为重叠任务分配不重叠泳道，颜色与步骤类型一致，并在悬停时显示输出、类型、rule 和精确耗时。
- AC-005.3：系统应当生成至少以下可解释提示：累计时间最高类型、最慢单步、平均并行度偏低候选、构建尾段长任务候选；没有足够证据时不显示肯定性结论。
- AC-005.4：用户按输出文本或步骤类型过滤时，最慢任务表和时间线应当同步过滤；总体摘要和类型汇总仍明确表示它们基于完整当前批次。
- AC-005.5：当记录很多时，时间线可以限制绘制最慢的 5000 条记录，但必须显示截断提示，统计和表格数据不得因此改变。

### REQ-006：提供清晰、可恢复的桌面交互

**用户故事：** 作为日常使用者，我希望软件状态和错误清楚、操作不会卡死或丢失已有结果。

- 优先级：Must
- 前置条件：应用已启动。
- 结果/副作用：提供可重复分析的单窗口工作流。

#### 验收标准

- AC-006.1：初始界面应当展示用途说明、路径输入、选择按钮和分析按钮；在首次成功分析前不展示伪造数据。
- AC-006.2：加载成功后，系统应当显示当前日志绝对路径、格式版本、有效/忽略记录数、manifest 匹配状态和批次局限提示。
- AC-006.3：加载失败或用户取消选择时，最近一次成功分析应当继续可见，用户可修改路径后重试。
- AC-006.4：窗口在 1280×760 时所有核心区域可访问；在较小窗口中应通过滚动区或可调整分隔器访问内容。
- AC-006.5：应用应当提供“关于分析口径”入口，解释日志字段、推断批次、累计时间和非严格关键路径限制。

## 边界、错误与状态转换

| 场景 | 预期行为 | 关联 ID |
|---|---|---|
| 输入是普通非 `.ninja_log` 文件 | 拒绝并保留已有结果 | REQ-001 |
| 目录有多个日志 | 排序展示选择；取消不改变结果 | REQ-001, REQ-006 |
| 日志最后一行未完整写入 | 作为坏行忽略并告警，其他记录可分析 | REQ-002 |
| v4 日志最后字段是命令文本 | 保留原值、不按 v5 十六进制哈希解释 | REQ-002 |
| 日志被 Ninja 重整、行序不能代表真实运行 | 显示“推断批次”限制，不宣称精确会话 | REQ-003, REQ-006 |
| `build.ninja` 缺失或输出未匹配 | 使用输出特征分类并显示回退状态 | REQ-003 |
| 全部任务零耗时 | 时间线显示零跨度空态，平均并行度为 0 | REQ-004, REQ-005 |
| 过滤后无任务 | 表格/时间线显示无匹配状态，完整批次摘要保持 | REQ-005 |
| 第二次加载失败 | 保持前一次成功数据和界面 | REQ-006 |

## 约束、假设与风险

### 已确认约束

- 必须使用 C++、CMake、Qt（FACT-001）。
- `.ninja_log` 分析必须只读，不能通过 `ninja -t recompact` 改变用户日志（目标/非目标）。
- 本轮没有真实用户样本（FACT-009），验证使用由官方格式派生的合成数据。

### 待验证假设

- ASM-001：绝大多数 CMake/Ninja 构建把 `.ninja_log` 与 `build.ninja` 放在同一目录；实现仍提供有限上行查找和回退分类。
- ASM-002：用户接受首版把一次 Ninja 运行称为“推断批次”，不要求严格恢复历史构建会话。
- ASM-003：首版以桌面源码交付和本机应用构建为完成，不要求签名安装包。

### 风险

- RISK-001：日志追加/重整语义会让历史行和时间线被误解。缓解：默认最后推断批次、醒目标注口径、提供全部记录但保持警示。
- RISK-002：Ninja manifest 语法包含转义、隐式输出和 include/subninja。缓解：只做用于输出-rule 映射的保守解析，未识别时回退，不影响核心日志统计。
- RISK-003：仅按规则/文件名无法证明 CPU/I/O 根因。缓解：提示使用“候选”和数据依据，不输出硬件根因断言。
- RISK-004：10 万条任务全部绘制会拖慢 UI。缓解：核心全量统计，时间线只画有明确提示的上限集合。
- RISK-005：旧 Qt6 Kit 与新 SDK 的链接元数据不兼容。缓解：只在 Apple、Qt6、系统找不到 AGL SDK 库且 wrapper target 存在时过滤该冗余链接项；QtGui 自身运行依赖和 Qt5 对照构建均需验证。

| ID | 类型 | 涉及需求 | 发现 | 决议/接受风险 |

| ANA-002 | 隐含假设 | REQ-003, REQ-005 | 原始日志可能跨多次构建且可能被重整 | 批次命名为“推断”，不将结果称为真实会话/关键路径 |
